# 05. Интеграция RuStore Pay SDK (подписки)

> ⚠️ Точные artifact-координаты SDK, сигнатуры колбэков и формат ответа покупки сверить с официальной документацией RuStore в Консоли (docs/00 #5). В коде — интерфейс `SubscriptionDataSource`; реализация `RuStorePayDataSource` пишется после сверки API; до этого — `FakeDataSource` для разработки и моков модератора.

## 1. Товары в Консоли (создать на неделе 3)
| SKU (productId) | Тип | Цена | Период | Примечание |
|---|---|---|---|---|
| `krug_premium_month` | подписка | 599 ₽ | 30 дней | стандартный период |
| `krug_premium_year` | подписка | 2 490 ₽ | 365 дней | основной оффер |
| `krug_premium_lifetime` | разовая покупка (non-consumable) | 6 990 ₽ | — | якорь |
Оба SKU-подписки: **бесплатный период 3 дня** (free trial — механика консоли, «только один раз на пользователя», при пере-оформлении — сразу стандартный период). Стартовый период (например, первый месяц 99 ₽) — включить A/B позже, не на старте. Grace-период: 7 дней (доступ сохраняется при неудачной оплате, повторные попытки — на стороне RuStore).

## 2. Клиентский флоу покупки
1. Paywall → выбор тарифа → `SubscriptionDataSource.purchase(sku)`.
2. Шторка RuStore Pay SDK (карты МИР/СБП/SberPay; RuStore закрывает ФЗ-376 комплаенс).
3. Колбэк успеха → **обязательная верификация статуса** через SDK (queryPurchases/getPurchaseState) → запись `SubscriptionState(status, sku, expiresAt, tokenHash, lastVerifiedAt=now, source=VERIFIED)` в Room.
4. purchase_success в аналитику; экран «Premium включён».
Колбэк ошибки/отмены → purchase_failed {reason_enum: cancelled|network|declined|unknown}; денег не списано — честный текст (docs/02 §9).

## 3. Проверка статуса и офлайн-кэш
- Источники истины: RuStore SDK (verifiable) > локальный кэш.
- При старте приложения и при каждой Premium-проверке: если сеть есть — тихая верификация; если нет — кэш: `now - lastVerifiedAt ≤ 72 ч` → считаем Premium (source=CACHED, «офлайн-льгота»); > 72 ч → мягкий лок: Premium-функции помечены «требуется проверка подписки (нужен интернет)», **Free-функции и напоминания работают всегда** (FR-29).
- Lifetime: покупка non-consumable — кэш lifetime можно держать дольше (7 дней), т.к. отзыв редок и возможен refund-колбэк.

## 4. События жизненного цикла
| Событие | Обработка |
|---|---|
| Покупка успешна | status=ACTIVE_*, expiresAt из ответа |
| Продление | RuStore списывает сам (за 8 ч до конца периода, по документации консоли); при следующем verify — обновление expiresAt |
| Неудачная оплата | RuStore grace ≤14 дней: статус GRACE, Premium сохраняется; баннер «проверьте способ оплаты» со ссылкой на управление подпиской RuStore |
| Отмена пользователем | отмена в RuStore (консоль пользователя); статус ACTIVE до конца периода → EXPIRED; в приложении — экран «Моя подписка» с кнопкой «Управлять в RuStore» |
| Истечение триала | RuStore списывает стандартную цену; если оплаты нет/отмена → FREE. За 1 день до конца триала — локальное уведомление-напоминание о условиях (прозрачность) |
| Возврат (refund) | через консоль разработчика; по verify → FREE; данные не удаляются |
| Восстановление покупки | кнопка «Восстановить» → queryPurchases по SKU → восстановление статуса (новый телефон/переустановка) |

## 5. Таблица состояний подписки
| Состояние | Что видит юзер | Premium-функции | Триггеры |
|---|---|---|---|
| FREE | плашка «Free», напоминания работают | ❌ (лимиты PRD) | мягкие тизеры; полный paywall ≤1/сут |
| TRIAL_ACTIVE | «Пробный период, осталось N дней», дата списания | ✅ | D2: онбординг-PDF; D3: «спасибо, что попробовали» |
| TRIAL_EXPIRED → FREE | баннер «попробуйте год за 2 490 ₽» | ❌ | paywall при следующем триггере; без пуш-давления |
| ACTIVE_MONTH/YEAR | галочка Premium, дата продления | ✅ | перед продлением — пуш «продлеваем завтра» (прозрачность) |
| LIFETIME | галочка «навсегда» | ✅ | — |
| GRACE | баннер «оплата не прошла, доступ временно сохранён» | ✅ | ссылка на оплату в RuStore |
| EXPIRED | «Premium истёк {дата}. Данные на месте» | ❌ | winback-оффер (промокод −50% на год) |
| UNKNOWN_OFFLINE | «Premium: проверяем подписку при появлении сети» | ✅ ≤72 ч, потом лок | не блокировать Free |

## 6. Безопасность и логирование
- Purchase token — только хеш в локальной БД; полные payloads — в приватные логи (не в аналитику).
- Все решения о доступе — по верифицированному статусу, не по «локальному событию покупки».
- События: purchase_started{sku}, purchase_success{sku}, purchase_failed{reason}, subscription_state_changed{from,to,source}, restore_started/success/not_found, trial_reminder_shown.
- Никаких внешних платёжных ссылок внутри приложения (правила RuStore); веб-оплата — только вне приложения для legacy-сценариев, не рекламируется.

## 7. Тесты (sandbox консоли)
Покупка каждого SKU; отмена и пере-оформление (trial не должен повторяться); refund; офлайн-кэш ( airplane-mode 72 ч); переустановка → restore; истечение триала (песочница эмулирует время — уточнить в консоли).

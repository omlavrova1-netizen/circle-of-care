# 08. План разработки 6–8 недель (соло)

## Неделя 1 — фундамент
**Цель:** каркас, БД, онбординг. **Задачи:** gradle/Hilt/Compose/nav, Room v1 (все сущности), DataStore, онбординг 4 шага (без OEM-экрана), профиль подопечного, AppMetrica-обёртка. **Результат:** проход онбординга до «Сегодня». **Критерии:** сборка CI, FR-01, онбординг-события в AppMetrica. **Риски:** SQLCipher/Keystore глючат на API24 — закладывать 1 день буфа. **Вырезать:** фото подопечного.

## Неделя 2 — лекарства + напоминания v1 (самая рисковая)
**Цель:** полный цикл «лекарство → будильник → подтверждение». **Задачи:** формы лекарства/расписания, генерация слотов, ReminderScheduler (exact+fallback), receiver, уведомления с действиями, IntakeLog-машина состояний. **Критерии:** на Xiaomi-эмуляторе и реальном устройстве: 3 времени в день → уведомления в срок, «Принято» из шторки. **Риски:** OEM-убийцы; точные будильники. **Вырезать:** тихие часы.

## Неделя 3 — надёжность напоминаний + повтор/пропуск
**Цель:** reconciler, boot/time receivers, повторы, «Не принимал» с причиной, OEM-экраны, тихие часы. **Критерии:** reboot → слоты восстановлены; airplane на время срабатывания → «пропущено» после включения. **Риски:** лимиты exact alarms. **Вырезать:** кастомные интервалы повторов (P-фича — позже).

## Неделя 4 — дневник, визиты, экстренная карточка
**Цель:** FR-15/16/02, документы (загрузка/просмотр/лимит). **Критерии:** запись с фото, лента, карточка-шаринг PNG. **Риски:** нет. **Вырезать:** поиск по дневнику.

## Неделя 5 — PDF и пакет передачи
**Цель:** базовая карта (Free), расширенный отчёт (P), пакет ZIP, backup/restore. **Критерии:** PDF читается врачебными ридерами; backup↔restore без потерь. **Риски:** вёрстка PDF под крупный шрифт. **Вырезать:** тренд-графики (таблицы достаточно).

## Неделя 6 — монетизация
**Цель:** RuStore Pay SDK (после сверки API), товары в консоли, sandbox-покупки, paywall+триггеры+лимиты, «Моя подписка», restore, grace/офлайн-кэш. **Критерии:** таблица docs/05 на sandbox; лимиты Free работают. **Риски:** задержка подключения монетизации → начинать неделю с заявки. **Вырезать:** стартовый период A/B.

## Неделя 7 — полировка + бета
**Цель:** тёмная тема, крупный шрифт, доступность, пустые/ошибочные состояния, приватность-экран, дисклеймеры, демо-данные, сборка beta (APK в закрытый TG-канал 20–30 семей). **Критерии:** 15+ фидбеков, фикс критичных багов; D1 beta ≥40%. **Риски:** вал багов — резерв. **Вырезать:** биометрия-замок.

## Неделя 8 — листинг и подача
**Цель:** ASO-материалы (docs/11), юридические URL, финальная сборка AAB/APK, подача в RuStore, ответы модератору, план GTM (docs/12) готов к запуску. **Критерии:** заявка отправлена. **Риски:** 1–2 круга модерации — буф. **Вырезать:** нельзя — релиз.

## Скоупы
- **MVP (v1.0):** всё из PRD Must + Should (PDF, дневник, визиты, остатки, лимиты, paywall, backup, OEM-экраны, демо-режим).
- **v1.1 (4–6 недель после релиза):** виджет «сегодня», остаток-прогнозы, чек-листы полностью, тёмная тема-полировка, RuStore Push (если доступен), winback-экран, подписка-подарок.
- **v2.0 (после метрик):** облачная семья с согласием (юрист!), роли/дежурства, «умные» алерты, интеграции (аптека/ЕМИАС — по юридической проверке), iOS по решению.
